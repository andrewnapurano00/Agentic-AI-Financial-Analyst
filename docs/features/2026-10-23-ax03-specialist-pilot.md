## Implemented boundaries

Typed contracts live in deep_research/specialist_contracts.py; orchestration and saved-contract eligibility in specialist_workflow.py; direct structured provider calls in providers/research_specialists.py; isolated controls/results in ui/research_specialists.py. The shared saved overview supplies source model configuration in both engines. Model output cannot mutate original evidence, reports, portfolio inputs, committees or exports.

Eligibility covers twelve named existing metric contracts only, with matching row/source values, correct units/currency/date, unique successful source IDs, explicit currency, canonical applicability and current methodology. Existing window() revalidates four consecutive fiscal-quarter metadata. Supported multiples, leverage and matched-balance returns get deterministic arithmetic checks. Retrieval freshness: quote inputs one day, other inputs thirty days. Observation-age limits: quotes seven calendar days, current TTM/latest balances two hundred days, historical matched balances up to eight hundred days. Unknown/inferred currency, missing dates and stale/invalid metadata fail closed per metric; absent metric families keep the result partial. These are disclosed pilot eligibility rules, not proof of live financial accuracy or AX-04 completion.

The initial specialist requests are separate and have disjoint fundamentals versus valuation/risk metric projections. A single exact-name saved_metric_lookup can expand one specialist packet; it makes zero network calls, and at most one extra model invocation follows. No retry after timeout. A failed continuation preserves the first interpretation. The lead deterministically reconciles stances and preserves named disagreement; it never invents a consensus recommendation. Optional existing committees remain separate and do not automatically consume pilot outputs.

Per run: three model attempts maximum, one local tool dispatch/continuation maximum; ninety-second scheduling deadline and post-response deadline validation; each HTTP client has at most twenty-five-second timeout and zero retries. These are client/scheduling bounds, not a hard operating-system cancellation guarantee. Each complete request is capped at twenty-four thousand UTF-8 bytes (at most seventy-two thousand across three attempts), responses twelve thousand bytes, completion allowance twelve hundred tokens each / thirty-six hundred total. There is no hard dollar ceiling when prices/failed usage are unknown. This action is separately acknowledged and outside the saved report's original model-cost budget. Actual available token counts are recorded by task; timeout usage remains unknown.

Structured observations must exactly match evidence ID/value/unit/currency/serialized period and company/task identity. Numerical prose is rejected; prose semantics remain unverified. Prompts mark user/provider text untrusted, give the model no callable tools and expose no private reasoning. A fixed allowlist rejects arbitrary metric names/URLs. Saved pilot output has a source fingerprint, task/usage trace and source/check audit; changed evidence warns without rerunning. Fewer usable specialists on a later attempt preserves the prior result and exposes the new failed/partial attempt separately.
