## Design note ? offline foundations are not a monitoring service

`monitoring/models.py` captures a frozen, credential-filtered model snapshot and fingerprint after existing optimizer validation. Holdings/weights/cash reconcile within 1e-9; source chronology remains explicit. No raw investment objective is retained. Saved thesis text is labeled opinion. The UI requires an explicitly saved advisor result plus consent, retains at most six immutable plans and keeps activation disabled. It creates no SQLite database, task or scheduler.

`monitoring/ledger.py` is an explicitly invoked offline SQLite rehearsal. Owner strings are namespaces, not authenticated principals. Plans/events are immutable; duplicate IDs with identical evidence reuse state, changed evidence under an existing ID is rejected. Claims have random lease tokens and sixty-second leases, with at most three attempts. Default budget is twenty distinct events (configurable at registration from one to one hundred), paid-model budget is zero. Disable cancels queued/inflight work; credential-scope/declared-expiry checks run before enqueue and commit. Restart/retry uses the original stored model/event, never caller-modified lease payload. A committed advisory is unique by owner/plan/event; explicit decisions are idempotent and conflicting replacements rejected. Approval/rejection records never mutate portfolios.

Concentration drift revalues the original fixed mix by supplied new-price/old-price ratios, leaves cash unchanged and normalizes once to the revalued account. It compares top-level position/category/cash constraints and proposes review of the original mix, with old/new values and dated evidence. Exact holding coverage, matching source/currency, fresh retrieval (fifteen minutes), quote age (seven days), chronology and explicitly declared verified same-share-basis evidence are required. No split adjustment is inferred; source/adjustment truth is not independently certified. This is why a live data adapter cannot be substituted for the rehearsal. Earnings, estimate revisions, ETF look-through, live entitlements, transaction costs and forecast risk are unavailable.

No active scheduler, browser loop, provider collection, model routing, notification transport, authenticated worker API, simulated execution or broker method is added. `monitoring.activate_monitoring()` always refuses activation; there is no environment flag or UI override. Production identity, durable authorized isolation, source/corporate-action/entitlement adapters, advisor reuse/risk qualification and AX-10 storage/security gates must be separately verified. This does not certify a deployable job service or complete AX-08.
