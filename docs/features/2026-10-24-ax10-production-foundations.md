## Delivered design and threat boundary

Active controls:

- `utils/logging_utils.py` accepts fixed event/category names, validated UUID lineage, bounded finite counts/times/costs, model families and opaque hashed source IDs. Free text, URLs, prompts, holdings, raw errors/traces and arbitrary nested metadata are dropped before handlers and filtered again by the formatter. ContextVar run scopes remain separate across threads and unwind on exceptions. Estimated cost and actual cost fields remain distinct; unknown actual billing is never synthesized. FMP and existing chat instrumentation adopt this boundary; universal stage/model usage instrumentation remains open.
- `security/provider_limits.py` and shared `providers/fmp_http.py` enforce process-local credential scopes using keyed hashes, 300 logical requests/minute, eight concurrent per credential, 64 globally and a bounded 4096-entry registry. Five transient failures open a 30-second circuit with one recovery probe. GET retries stay two, but Retry-After/backoff sleeps cap at two seconds. Timeouts cap at five seconds connect/thirty seconds read per attempt. Only HTTPS FMP destinations are allowed; redirects, embedded credentials, queries/fragments and unsafe ports fail before transport. Provider errors omit raw response/error bodies and external exception chains. Limits return explicit errors so existing pages preserve valid results; no model fallback is introduced. These are credential/process limits, not distributed authenticated per-user budgets or universal provider/model coverage.
- `main.py` uses unique request UUIDs, a 12-step chat recursion limit and bounded session-scoped graph/repair resources. Equal credentials no longer imply shared conversation memory. `security/runtime.py` blocks hosted and unknown modes before workspace controls; both main and focused advisor launchers apply it. Docker defaults to hosted/blocked; the derived offline verification image explicitly uses local mode. Local mode is a trusted desktop workflow, not authentication, and must not be exposed as an unauthenticated hosting workaround. The release manifest cannot enable hosted mode even with every gate declared passed. Monitoring remains disabled.

Checkpoint foundation:

`security/checkpoints.py` is an explicitly invoked service with AES-GCM encrypted sanitized saved research/portfolio state, keyed owner namespaces and owner/run/revision associated data. It accepts a server-managed 32-byte key rather than storing it in the database. A trusted future identity adapter may issue signed short-lived scope grants only after authentication; `issue_for_authenticated_owner` itself is not authentication. Read/write/export/delete enforce signature, owner, scope and expiry. Transactional revision compare-and-swap prevents silent overwrite. Partial/failed/complete status and original saved values remain unchanged on restart. Limits: one-megabyte plaintext row, twenty rows/ten MB ciphertext per owner, 1000 rows/100MB globally; volume quotas/retention are still deployment work. UUID run IDs cannot become filenames. Root/database symlinks are rejected; server-owned POSIX permissions or Windows ACLs and a non-hostile filesystem are required. This is not protection from privileged administrators/filesystem races.

No page creates this database, issues grants, automatically saves/resumes reports or dispatches jobs. There is no fabricated identity provider, browser token API, scheduler or automatic paid resumption. Offline backup/restore is a SQLite backup test, not a hosted operational backup or rollback. Replacing the key denies access to old data/grants; managed key migration/rotation and revocation integration remain open. Existing session-only behavior is disclosed in README.
