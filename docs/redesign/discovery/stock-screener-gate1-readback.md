## Intended result and scope

The [implementation contract](../implementation-contract.md) calls for compact base filters, labeled server ranges, enrichment and post-screen disclosures, an explicit **Run Screener**, and a saved result table that stays usable when configuration is reopened. Use the shared navy/gold shell and scannable table treatment from the approved image package; no dedicated Screener image supplies new figures or capabilities. The current eight-route identity remains `Stock Screener`. This is a page-only composition proposal for `ui/stock_screener_tab.py` presentation. `main.py`, `loadui.py`, shared shell, provider transport, metric enrichment, filter arithmetic, caching, defaults and export schema are outside scope. A shared API or routing change returns to the integration owner.

`main.py` routes `active_workspace=Stock Screener` to `render_stock_screener_tab(fmp_api_key)`. A missing FMP key displays an error and still calls `_render_saved_screener`, then returns before the form. With a key, `stock_screener_form` shows Country (US), Exchange, Sector and Industry contains; expanded Server-side range filters with wide-open defaults, cap/price/volume/beta/dividend ranges, page size and max pages; expanded Enrichment + final output controls with metrics cap, final display cap and RSI period; collapsed Post-screen metric filters with enable switch, missing-metric policy and all fifteen ratio/technical range sliders. These sliders render even when the enable switch is off; they are applied only after explicit Run when enabled. Preserve all options, thresholds, units, defaults and form grouping.

Only the form's **Run Screener** calls the cached FMP server screen, optionally filters industry text, takes at most `metrics_max` screened tickers for enrichment, optionally applies advanced filters, then caps/sorts the final output by market cap. The server request retains active-trading true, ETF/fund false, filter ranges, per-page limit and max pages. Fetched-page count and `meta.errors`/`meta.warnings` captions appear only after both the server screen and industry-filtered screen remain nonempty; earlier empty-return paths suppress those metadata captions. Missing values follow the existing `ignore_missing` setting. No LLM/model call exists on this page. An ordinary filter edit, disclosure open, result view, CSV download or company selection makes no paid call.

Successful output stores `stock_screener_payload` with `generated_at` and the final results DataFrame. `_render_saved_screener` is invoked after success and on ordinary rerun, including when filters are reopened. It captions saved generation time as **not a new retrieval time**, displays the top-row count and sort basis, and offers a formatted table with the existing 24-column intersection (identity, sector/industry, price/cap/volume/beta, valuation, profitability, debt/liquidity, RSI, moving-average distances and description). The CSV exports the raw final DataFrame, not the formatted display subset, as `stock_screener_results.csv` with `text/csv`. `screener_focus` selects a saved ticker; **Open Introduction** (`screener_open_intro`) queues the existing typed `ResearchContext` with `analyze` intent. Do not add a row event that silently replaces this keyboard-usable selector.

## Proposed page layout and conflicts

Use one compact title/evidence row, then a short base-filter grid and the three original labeled disclosures, with the Run action at the end of the form. Show a saved-results panel below that stays visible when disclosures open or close. Give the result table the full main width with local horizontal scrolling at 1024 and 390 px; keep CSV and company selector/action adjacent to the table. Preserve provider errors, empty server screen, empty industry match, no enriched rows, empty post-filter result and partial page warnings near the corresponding stage. Do not turn configuration readiness or the saved-run clock into evidence freshness.

The source has an important pre-existing limitation: an explicit new Run that returns early at the empty server, industry, enrichment or post-filter gate leaves the prior payload in session but does **not** call `_render_saved_screener` during that failed rerun. A subsequent ordinary rerun shows it. A visual-only relocation must not claim that the previous result was visibly preserved during that failed run. If the builder chooses to repair that recovery behavior, treat it as a separately reviewed behavioral change with focused tests. The module also stores `FMP_API_KEY` in a module global; session-isolation review remains a separate reliability issue, not a cosmetic change. The inline `.cardbox/.subtle/.scrollarea` CSS is light-themed and may conflict with the navy shell; replace only after proving all active uses remain legible, without generated Streamlit selectors or a provider change.
